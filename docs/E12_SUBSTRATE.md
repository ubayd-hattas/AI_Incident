# E12 substrate — retained-only boundary and coverage/delay core

Role: implementer (Sam), under `docs/X13_RUN_CONTRACT.md` §4/§9's own authorization boundary — "Repair work and
synthetic fixtures may proceed while blocked; semantic scoring against real captures may not." This is **not** a
full E12 implementation. It is the part of E12 that is buildable and testable today, without the real A11
fragment-alternatives schema (acceptance-matrix item C), whole-DSE occurrence-census completeness (item D), or
machine-readable eligibility mask (item E) — none of which exist yet, and all of which are Alex/Aaron/Jaswin's
annotation-authorship work, not something this pass invents.

## What this is

`src/ebe/evaluator.py`:

- **`RetainedSnapshot`** — the only type the coverage/delay core may consume. `from_collector_result` builds it
  exclusively from `CollectorResult.retained_evidence` (genuinely retained bodies) and `.feed_polls` (genuinely
  delivered/charged feed context) — never from `body_results`/`capture_attempts`/audit logs, per the SS4 firewall.
- **`Fragment`/`Proposition`** — a synthetic OR-of-AND representation matching SS4's algebra
  (`core_alternatives`/`context_alternatives`, each an AND-list of fragment IDs; a proposition is covered if any one
  alternative's fragments are all satisfied). **This is scaffolding for testing the evaluator's logic, not a
  proposal for the real annotation schema** — the real schema requires source-projection-to-canonical-offset
  mapping, human-reviewed occurrence census, and eligibility-with-reasons that this module does not and should not
  invent.
- **`validate_population`** — an A05 denominator firewall: rejects duplicate evidence IDs, dangling fragment
  references, and eligible critical propositions with no core alternative, before any coverage is computed.
- **`compute_core_coverage`/`compute_context_coverage`** — micro coverage only (equal weight per proposition), per
  SS5. Explicit NA handling: an empty denominator reports `percentage=None`, never a fabricated 0.0 or 100.0.
  Ineligible propositions are excluded from both numerator and denominator, tracked separately.
- **`compute_delay`** — per SS5's rule: earliest acquisition time of a satisfied core alternative (the max of its
  fragments' times — "multi-part acquisition time is the latest component"), minimized over alternatives ("minimize
  over valid retained alternatives"), minus the proposition's earliest eligible support time. Three distinct
  statuses: `retained`, `unretained` (never scored as zero), `na_unknown_support`.

`tests/test_evaluator.py`: 12 hand-scored acceptance tests, every expected value computed in the test body, not
generated by the evaluator. Covers: duplicate-support/earliest-acquisition, cumulative-body satisfaction,
context-independent-of-core, byte-level encoding consistency, NA-eligibility exclusion, empty-denominator NA, both
population-firewall rejections, and all three delay statuses. One test
(`test_eviction_poisoning_real_collector_evicted_body_never_counts_as_retained`) drives the **real**
`Observer`/`PeriodicCollector` (capacity_bytes=0) to prove the firewall holds against genuine collector output, not
just a hand-built snapshot — confirming a fragment relying on content the real collector saw and discarded is
correctly scored as uncovered.

## What this deliberately does NOT do

- No F, PCD-R, archive ledger, phase-distribution statistics, group/leave-one-out robustness, or any §8 output
  CSV/figure — those are separate, larger X13 gates.
- No real annotation file (`evidence.jsonl`, `occurrences.jsonl`, `rubric.md`, `splits.json`) is read, scored, or
  touched anywhere in this module or its tests.
- No fragment definitions, eligibility dispositions, or occurrence-census completeness were invented on the
  annotation team's behalf — the `Fragment`/`Proposition` types exist only to drive synthetic tests.

## What remains before this can score real A11 data

Exactly the acceptance-matrix items already on record in `docs/PROJECT_STATUS.md`:

- **Item C** (typed fragment/context alternatives): `evidence.jsonl` still uses flat revision/event-ID
  `support_bundles`, not the OR-of-AND fragment algebra this module's `Fragment`/`Proposition` types assume.
  Converting real evidence to this shape is annotation-authorship work.
- **Item D** (occurrence-census completeness): a whole-DSE search for every core/context fragment has not been
  performed; the real `occurrences.jsonl` is not yet a candidate-search/rejection log.
- **Item E** (eligibility mask): no machine-readable eligibility field/file exists yet with exclusion reasons;
  `Proposition.eligible`/`eligibility_reason` here are placeholders a real loader would need to populate from that
  mask once it exists.

Once those three land, the missing piece is a loader that converts real `evidence.jsonl`/`occurrences.jsonl`/the
future fragment and eligibility files into `Proposition`/`Fragment` objects — that loader is straightforward once
the schema exists, and is intentionally not written yet (writing it now against a schema that doesn't exist would
mean guessing the schema).

## Completion report

1. **Retained-only firewall:** implemented (`RetainedSnapshot`) and poison-tested against real collector output
   (capacity_bytes=0 case) — confirmed a body the real collector saw but never retained cannot inflate coverage.
2. **Coverage core:** micro core/context coverage implemented per SS5; NA-empty-denominator and
   ineligible-exclusion rules implemented. Group/phase/macro robustness deliberately deferred.
3. **Delay core:** implemented per SS5's exact rule (latest-component-per-alternative, minimize-over-alternatives,
   three distinct statuses).
4. **Synthetic acceptance:** 12 hand-scored cases, all matching; full 115-test project suite passes unchanged.
5. **Bugs found in the process:** two in this module's own tests, both fixed before landing — an eligible critical
   proposition fixture with no core alternative (correctly rejected by the firewall it was meant to test around,
   not a firewall bug) and a duplicate-ID test whose fixture also had empty core alternatives, so it was raising
   for the wrong reason; both fixed to isolate the actual rule under test.
6. **What remains before real scoring:** acceptance-matrix items C (fragment schema), D (occurrence-census
   completeness), E (eligibility mask) — all annotation-authorship work, matching `docs/PROJECT_STATUS.md`'s
   existing record exactly.
7. **Confirmed:** no real annotation file was read, scored, or modified by this work.
