## 2. X01 — partial repair, not full closure

**Original concern:** GET dispatched before an earlier checkpoint C but completed after C was charged as completed success and downloaded bytes; only admission was correctly clipped.

**Sam changed:** `Observer._non_body_metadata` separates feed/directory transfer from GET headers. `costs(checkpoint)` replays `_audit` response times, assigning post-C/undated completions to pending with no header/body/outcome weight. `CollectorResult.outcome_counts` applies the same cutoff. `costs()` without C deliberately retains eager totals.

**Independent finding:** correct for the shipped collectors' fresh-prefix usage. Synthetic save at t0+10s, dispatch at t0+60s, C=t0+120s: across P/PD/PCD/E30, completion at C−1us and C yields `(attempts,success,body bytes,pending,admissions)=(1,1,1,0,1)`; C+1us yields `(1,0,0,1,0)`. Boundary convention is inclusive completion, exclusive live dispatch.

**Still open:**

- `costs(C)` filters by response time, not request time; `_body_requests` and non-body counters are cumulative. Poll at minute1, GET at minute5, poll at minute2 (currently allowed), then `costs(minute2)` reports one body request and one pending request, though dispatch is after C. Either reject as-of queries after any operation beyond C (with a fresh-prefix-only API contract) or maintain properly checkpointed operation ledgers. Terminal exceptions must be explicit.
- The earlier-checkpoint diagnostic `BodyResponse` and observer audit still disclose future outcome/body. At phase45s, 30s delay, C=minute2, adding an overwrite at +130s changes returned diagnostic body from invented `A` to `FUTURE`, while checkpoint costs and retained exports correctly remain identical. No current scheduler uses this body, but the original diagnostic/future-prefix requirement is not closed.
- No committed C−1us/C/C+1us regression matrix was added by the fix; existing global-T and zero-delay suffix tests are insufficient. Add BODY/missing/unknown/BU/ambiguous/unsupported and delayed suffix cases for periodic and E.

**Side effects:** `costs(C)` now rescans the whole audit journal, O(requests), and has different semantics from `costs()`. This shared overhead belongs in X04, not modeled retained evidence or a free policy-specific accounting exception.

## 3. X02 — remaining causal API defects

**Original concern:** reverse-time discovery, future delayed body available at dispatch, and incomplete/one-shot F-mode separation.

**Sam changed:** GET rejects times before the most recent poll; polling rejects any prior successful terminal directory. Both additions are policy-neutral and close the specific poll→backdated-GET reproduction and missing directory→feed guard.

**Independently reproduced remaining paths:**

1. `poll_feed(minute1); get_body(title, minute5); poll_feed(minute2)` succeeds: no common operation-time guard.
2. Calling `terminal_directory()` twice succeeds and charges two directories: no one-shot guard.
3. `terminal_directory(T); get_body(discovered_title, minute1)` returns BODY: directory discovery has no causal time guard on GET.
4. At minute1, dispatch with delay30s immediately returns the body of a mutation at +75s. `_observe_state(response_time)` is eagerly called and its result directly returned. No completion-only availability API exists. `costs()` likewise exposes eager outcomes.

Current P/PD/PCD/E loops only append responses and later replay admissions; they do **not use future bodies for scheduling**. That supports a narrow fairness finding, not a claim that no future information is exposed. Before online repair/F/archive code, enforce a common clock, one-shot/mutually exclusive terminal mode and completion-only outcome availability. Preserve response-time current-body semantics and equal feed/discovery access. Failures must not partially mutate observer state.

**Side effect:** old audit tests that backdated GETs were rewritten to use delayed completions. That is a legitimate test correction, but it does not validate the remaining paths above or certify prefix-invariance of diagnostic histories.

## 4. A04 — safe ordinary path, incomplete integrity boundary

**Original concern:** zero-cap/oversize/evicted bodies survived in uncapped histories and could be mistaken for retained evidence.

**Sam changed:** both collectors now export immutable `RetainedEvidenceUnit` records exclusively from `store.retained_captures` and `store.body_for_capture(request_seq)`. That store lookup rejects evicted references. E12's `RetainedSnapshot.from_collector_result` reads only `retained_evidence` and delivered `feed_polls`, not debug body/attempt histories.

**Independent finding:** the ordinary adapter path genuinely fixes the immediate zero-cap leak. The existing poison test confirms no body evidence through that path. Both collectors use the same export logic; store admissions/dedup/FIFO were not changed.

**Not full original closure:**

- `RetainedSnapshot` discards request sequence, charged packet bytes, object ID/refcounts and cap/accounting provenance. It cannot validate packet/object linkage or S. The adapter does not cross-check retained packets against exported bodies.
- No snapshot hash, time, reference or cap validation exists. A synthetic body record with `body_sha256='BADHASH'` and capture at C+1minute scores as retained. Missing `retained_evidence` entries can silently become misses (the collector field defaults to `()`), rather than an integrity failure.
- Frozen dataclasses/type hints are not runtime whitelisting: arbitrary duck-typed snapshots/results can be supplied. E12 entry points must validate their approved input boundary, not rely only on callers reading a docstring.
- Full unretained body histories remain reachable in `CollectorResult`, and admissions are still batched after dispatch. Documentation labels them diagnostic, but no separate inaccessible replay/journal boundary or overhead measurement has been implemented. Streaming is required for PCD-R and must be schedule/accounting-equivalence tested on existing policies.
- The test named eviction poisoning uses **capacity zero**, i.e. never-admitted oversize rejection, not eviction of a previously retained body. Add actual eviction, shared-object/last-reference, standalone oversize without eviction, missing-object/hash tamper and diagnostic-poison fixtures.

**Side effect:** the new body-bearing export adds references/records outside modeled S and E12 builds another representation. Do not charge it as a second modeled capture, but measure it as harness/evaluator overhead. Retained-at-C scoring, ever-admitted journal and ever-downloaded diagnostics must remain separate.
